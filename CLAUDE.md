# ARC S2 Engineer arm — working conventions

Code-CAD robot arm in FreeCAD 1.1 Python (`%LOCALAPPDATA%\Programs\FreeCAD 1.1\bin\freecadcmd.exe`; pin this version).
Start with `cad/MAP.md` (generated). It lists every module, parameter file, interface, keep-out zone, and every part with the file:line that builds it.

## Where things live
- `cad/arm/`: the model, one module per subassembly. `arm_model.py` is a compatibility facade (`import arm_model as M`).
- `cad/params/*.toml`: named design inputs, with units and reasons. **Edit these, not literals in code.** `variant.toml` sets the active gripper (`GRIP` env var overrides it), the J1/J2 base drive (`BASE_DRIVE` env var: `GEARED` = rev B STS3215 + 3:1 spur stage, `DIRECT` = DM-J4340 direct drive, the Fusion "Rev A"; outputs and fingerprint `<grip>_direct`) and the release variant.
- `cad/interfaces/*.toml`: mating interfaces. Both mating parts build from the file (`cad/iface.py`), and `tools/check_interfaces.py` probes the geometry.
- `cad/envelopes/*.toml`: field keep-out boxes per task pose, each with a reason and a source.
- `cad/data/catalogue.toml`: purchased parts (mass, source, what to verify).
- `cad/out/<variant>/`: check results plus `manifest.json`, which records each run's status and inputs hash.
- `cad/out/<variant>/ARC_Arm_<Variant>.FCStd`: the maintained FreeCAD working document (one group per moving body, coloured, at STOW), generated by `cad/tools/working_doc.py`. Rebuild it after a design change: run it in the FreeCAD GUI for colours, or with freecadcmd for uncoloured geometry. A headless rebuild leaves any copy open in the GUI stale, so rebuild in the GUI before showing the model, then run `tools/check_working_doc.py` there (`import check_working_doc as W; W.main()`): it compares the open document part by part with the model. Its evidence goes STALE like any check. `*.FCStd` is stored in Git LFS.

- `fusion/`: Autodesk Fusion is the design master (team edits there). `snapshot/<rev>/` is each version exported as text; `checks/` compares it with the code-CAD. How to export, check and edit safely: `fusion/README.md`. One Fusion writer at a time; Codex (codex-fusion workspace) does Fusion placement work on request.

## Frames
- World/robot frame: x forward from the bumper, y left, z up from the floor.
- Gripper frame: x along the roll axis, TCP at (151, 0, −20), roll axis at z = −5.
- `jaw` = gap between the pad arcs at the TCP: pipe 13.8, donut 100, open 112.

## Workflow
1. Change a TOML value or a builder.
2. Run `tools/quick_check.py` (about 90 s with the model build). It covers envelopes, interfaces, gripper self-interference, mass/torque, fastener seating (every screw, pin and washer in its hole and bearing on a part) and the fingerprint, and shows FRESH/STALE evidence.
3. Refactors: `tools/fingerprint.py` must report MATCH for `GRIP=FOURBAR`, and for `BASE_DRIVE=DIRECT` (fingerprint `fourbar_direct`) when the base or a shared module changed. After an *intended* geometry change, re-record it (`FP_MODE=record`) and say which parts changed.
4. Milestones: run `check_interference.py` (about 4 min, ground truth). FEA and renders only on request.
5. Documentation is one PDF, `cad/docs/ARC_S2_Engineer_Arm.pdf`: an arXiv-style product summary with the requirements verification, rebuilt from the check results by `cad/docs/paper/make_paper.py` (needs `pdflatex`, e.g. MiKTeX). Change `cad/docs/paper/paper.tex` for wording; numbers come from `numbers.tex`, which is generated. There are no drawings: they are not required. Don't add parallel docs: README.md points to the PDF (design, evidence, open items), fusion/README.md (Fusion workflow) and sim/README.md; anything else is generated output.
6. New mates or limits go in `interfaces/` or `envelopes/` first, not as numbers buried in a builder. Both mating parts must build from the file. When you move a part, check its mate is in `interfaces/`; a standoff moved through a parameter once left its plate holes behind. `[pattern]` handles bolt circles and `[stations]` handles rows of holes, with an optional `[spacer]` side.
7. New gripper: add `arm/grippers/<name>.py` with `<name>_bodies()` and `<name>_placements(Hd, jaw)`, register it in `arm/bodies.py` GRIPPERS, and mount it on `interfaces/roll_hub__gripper_palm.toml`.

## Guard rails
- Release generators build the release variant only and refuse another `GRIP` or `BASE_DRIVE`: `export_fab.py`, `fea/run_fea.py`, `render/export_render.py`. The released package (rev B since 2026-11-19, `GRIP=FOURBAR`) in `fab/` and `fea/out` changes only on request. A non-release variant's STEP/BOM for migration: `tools/export_variant.py` -> `cad/out/<variant>/fab/`.
- In a running FreeCAD GUI session, call `arm.reload_all()` to pick up edits. Don't drive the GUI from `execute_code_async`.
- Run long jobs (full interference, FEA, renders) in the background.
- Deliverables live in this GitHub repo: the product summary is `cad/docs/ARC_S2_Engineer_Arm.pdf`. OneDrive is no longer used.
- A PreToolUse hook (`cad/tools/hooks/release_guard.py`) asks before any hand edit under `cad/fab/`, `cad/fea/out/` or `cad/render/out/`.

## Agent tooling
- Project skills in `.claude/skills/`: `verify` (which checks a change needs, before every commit), `fusion-change` (edit, snapshot, check and record a Fusion change), `codex-fusion` (hand Fusion placement work to Codex), `tooling-audit` (daily audit of this tooling against the latest docs).
- Docs MCP servers: `claude-code-docs` (Claude Code), `claude-platform-docs` (Claude API, Agent SDK), `openai-docs` (Codex). Check features there, not from memory.
- Tooling friction and fixes go in `cad/docs/tooling_issues.md` (one TI row each); audit runs go in its "Docs audits" table. `cad/tests/test_agent_config.py` checks `.claude/`.
- Bash: use absolute paths instead of a leading `cd`; wait on long jobs with `run_in_background` or Monitor, never `sleep`.
